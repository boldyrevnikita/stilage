# Описание формата сообщений для ML-сервиса
Примечание: все координаты и размеры задаются в миллиметрах (мм).

## Входные данные ML-сервиса

```json
{

    "file_id": "unuque_file_id_1",
    "available_zones": [
        {

            "id": 12

        {

            "height": 3000.0,
            "id": 22
        },
        .
        .
        .
    ],
    "restricted_zones": [
        {
            "boundary": [[1020, 2100], [1200, 2800], [1800, 2900], [1900, 2200], [1500, 2150]],
            "clearance": 200,
            "id": 13
        },
        {
            "boundary": [[3300, 6400], [3400, 6900], [3900, 6800], [3800, 6300], [3500, 6450], [3300, 6400]],

        .
    ],
    "road_zones": [
        {
            "line": [[0.0, 5000.0], [20000.0, 5000.0]],
            "width": 3000.0,
            "id": 15
        },
        {
            "line": [[30000.0, 20000.0], [40000.0, 20000.0]],
            "width": 5000.0,

    "cargos": [
        {
            "weight": 1000,

        }

        .
    ],
    "roads_width": 3000.0,

```

- `task_id` -- уникальный идентификатор задачи;
- `file_id` -- уникальный идентификатор файла, в котором находится чертеж склада;
- `available_zones` -- список доступных зон для расстановки стеллажей, где:
    - `boundary` -- ПРЯМОУГОЛЬНИК, задающий границы зоны в формате `[(x1, y1), (x2, y2), ...]`;
    - `height` -- высота зоны;
    - `id` -- уникальный идентификатор зоны, заканчивающийся на `2`;
- `restricted_zones` -- список специальных зон, в которых запрещенно (или невозможно) ставить стеллажи, где:
    - `boundary` -- МНОГОУГОЛЬНИК, задающий границы зоны в формате `[(x1, y1), (x2, y2), ...]`;
    - `clearance` -- необходимое свободное расстояние от зоны;
    - `id` -- уникальный идентификатор зоны, заканчивающийся на `3`;
- `cargos` -- список грузов, которые необходимо разместить на складе, где:
    - `weight` -- вес груза в килограммах;
    - `length` -- длина груза в миллиметрах;
    - `width` -- ширина груза в миллиметрах;
    - `height` -- высота груза в миллиметрах;
    - `quantity` -- количество грузов;
    - `id` -- уникальный идентификатор типа стеллажа, заканчивающийся на `4`;
- `road_zones` -- список специальных дорожных зон, где:
    - `line` -- линия, задающая проезд в формате `[(x1, y1), (x2, y2)]`;
    - `width` -- ширина проезда;
    - `id` -- уникальный идентификатор проезда, заканчивающийся на `5`;
- `roads_width` -- ширина дороги между стеллажами.
- `roads_height` -- высота дороги между стеллажами.

- `task_id` -- уникальный идентификатор задачи;
- `racks` -- список стеллажей, где:
    - `id` -- уникальный идентификатор типа груза, заканчивающийся на `4`, например, `14` или `24`:
        - `boundary` -- прямоугольник, задающий границы стеллажа в формате `[(x1, y1), (x2, y2), (x3, y3), (x4, y4)]`;
        - `sections_in_length` -- количество секций в длину;
        - `sections_in_width` -- количество секций в ширину;
        - `sections_in_height` -- количество секций в высоту (включая ярус под первой балкой);
        - `sections_in_height_special` -- количество секций в высоту у навесных стеллажей над проездом;
        - `upright_section` -- сечение стоек стеллажа в формате `[ширина, длина, толщина стенок]`;
        - `beam_section` -- сечение балок стеллажа в формате `[ширина, толщина стенок]`;
        - `beam_lengths` -- длины балок для каждого яруса (секции) стеллажа;
        - `pallet_size` -- размер поддона, который будет использоваться на стеллаже в формате `[ширина, длина]`;
        - `special_units` -- информация о том, что в `i`-ом ряду и `j`-ой секции стеллажа находится специальная секция (например, навесной стеллаж). `0` -- обычная секция, `1` -- навесная секция (над проездом);
        - `orientation` -- ориентация стеллажа. Если `0`, то стеллаж расположен вдоль оси `x` (горизонтально). Если `1`, то стеллаж расположен вдоль оси `y` (вертикально);
        - `rack_distance` -- расстояние между сдвоенными стеллажами. Если `null`, то расстояние не задано (например, для ординарных стеллажей).
- `warnings_and_errors` -- предупреждения и ошибки, возникшие в процессе работы ML-сервиса. Предполагается, что данная информация может быть полезна для пробрасывания на фронт.
- `success_predict` -- флаг успешности выполнения задачи. Если `true`, то задача выполнена успешно (модель отработала до конца). Если `false`, то задача выполнена неуспешно (модель не смогла выполнить задачу).
